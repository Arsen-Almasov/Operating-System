# Практическая работа № 8. Взаимоблокировки

## Цель работы

Воспроизвести взаимоблокировку потоков, изучить предотвращение deadlock, реализовать алгоритм банкира и обнаружение циклов в графе ожидания.

## Состав проекта

- `deadlock.py` — пример взаимоблокировки двух потоков.
- `deadlock_fixed.py` — исправленный вариант с единым порядком захвата блокировок.
- `banker.py` — вычисление Need, проверка безопасности и обработка запроса ресурсов.
- `bank1.txt` — безопасное состояние системы.
- `bank2.txt` — небезопасное состояние системы.
- `wait_for_graph.py` — обнаружение циклов в графе ожидания.
- `practical8_deadlocks.ipynb` — ноутбук Google Colab.

## 1. Воспроизведение deadlock

Запуск:

```bash
python3 deadlock.py
```

Два потока захватывают блокировки в разном порядке. Первый удерживает `lock_a` и ожидает `lock_b`, а второй удерживает `lock_b` и ожидает `lock_a`. В результате оба потока блокируются.

Для диагностики программа использует `faulthandler`, который печатает стеки потоков. В диагностическом выводе нужно найти места, где потоки ожидают получения блокировок.

В Google Colab зависший процесс запускается отдельно и ограничивается по времени. Для проверки в обычном Linux-терминале можно использовать `faulthandler` или инструмент `py-spy`.

## 2. Предотвращение взаимоблокировки

Запуск исправленной программы:

```bash
python3 deadlock_fixed.py
```

Все потоки захватывают блокировки в едином порядке: сначала `lock_a`, затем `lock_b`.

Это нарушает условие циклического ожидания: невозможно образовать цикл, в котором каждый поток удерживает следующий ресурс и ждёт предыдущий. Использование `sleep` само по себе не устраняет взаимоблокировку.

## 3. Алгоритм банкира

Формула:

`Need = Max - Allocation`

Алгоритм начинает с `Work = Available`. Он ищет незавершённый процесс, для которого `Need <= Work`. Если процесс найден, предполагается его завершение, а выделенные ему ресурсы возвращаются:

`Work = Work + Allocation[i]`

Если удалось завершить все процессы, состояние безопасно. Иначе состояние считается небезопасным.

Запуск:

```bash
python3 banker.py
```

Ожидаемые результаты:

- `bank1.txt`: безопасное состояние; допустимая последовательность `P1 → P3 → P4 → P2 → P0`.
- `bank2.txt`: `UNSAFE`.
- Запрос P1 `(1, 0, 2)` для `bank1.txt`: разрешён после проверки безопасности; одна допустимая последовательность после запроса — `P1 → P3 → P4 → P0 → P2`.

## 4. Обнаружение циклов

Запуск:

```bash
python3 wait_for_graph.py
```

В графе ожидания вершины соответствуют процессам, а ребро `Pi → Pj` показывает, что Pi ожидает ресурс, удерживаемый Pj. Алгоритм поиска цикла обнаруживает взаимоблокировку при стандартном предположении об одном экземпляре каждого типа ресурса.

## Контрольные вопросы

### 1. Почему упорядочивание захвата ресурсов исключает deadlock?

Если все потоки захватывают ресурсы в одном глобальном порядке, цикл ожидания возникнуть не может: поток, удерживающий ресурс с более высоким порядком, не должен запрашивать ресурс с более низким порядком. Следовательно, устраняется условие циклического ожидания, необходимое для взаимоблокировки.

### 2. Почему алгоритм банкира редко применяется в универсальных ОС?

Алгоритм требует заранее знать максимальные потребности процессов в ресурсах. В универсальных ОС потребности часто динамичны и заранее неизвестны. Кроме того, проверка безопасности добавляет вычислительные расходы и может задерживать выделение ресурсов. Поэтому алгоритм удобен для изучения и отдельных контролируемых систем, но неудобен как универсальное решение.
