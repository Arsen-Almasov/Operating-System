# Практическая работа № 5. Симулятор планирования CPU

## Цель
Реализовать алгоритмы планирования CPU и сравнить среднее время ожидания, оборота и отклика.

## Алгоритмы
- **FCFS** — первым пришёл, первым обслужен; невытесняющий.
- **SJF** — среди прибывших выбирается процесс с минимальным полным burst; невытесняющий.
- **SRTF** — вытесняющий вариант SJF, каждый такт выбирается минимальное оставшееся время.
- **RR** — циклическое планирование с квантумом `q=3`.
- **Priority** — вытесняющее планирование по приоритету; меньшее число означает более высокий приоритет.

При равенстве критериев выбирается более раннее прибытие, затем меньший числовой PID. В RR процессы, прибывшие к границе кванта, ставятся в очередь до возвращения вытесненного процесса.

## Запуск
```bash
python3 sched.py --algo rr --quantum 3 set1.txt
python3 sched.py --algo fcfs set2.txt
python3 sched.py --algo srtf set3.txt
```

Допустимые значения `--algo`: `fcfs`, `sjf`, `srtf`, `rr`, `priority`.

## Вывод по set3
В `set3` один процесс (`P1`) имеет длинный burst, равный 60, а остальные процессы короткие. Поэтому **SRTF обычно особенно хорошо обслуживает короткие процессы**: он может переключаться на более короткую работу, не заставляя её ждать завершения длинного процесса. Это уменьшает среднее ожидание/оборот, но длинный процесс может долго оставаться незавершённым. Для интерактивности также важно смотреть на среднее время отклика; RR распределяет CPU более равномерно.

## Контрольные вопросы

1. **Почему SJF нельзя напрямую применять в реальной ОС?**  
   ОС обычно не знает заранее точную длительность следующего CPU-burst. Она может только оценивать её по прошлому поведению процесса. Кроме того, SJF может приводить к голоданию длинных задач, если постоянно приходят короткие.

2. **Что происходит при кванте RR, стремящемся к бесконечности?**  
   Каждый процесс получает CPU на время, достаточное для полного завершения, прежде чем очередь переключится на следующий процесс. При фиксированном наборе процессов RR приближается к FCFS по порядку готовой очереди и теряет преимущество частого переключения контекста.
