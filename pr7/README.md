## Международное взаимодейсствие

## Вывод

В ходе практической работы были изучены основные механизмы межпроцессного взаимодействия. С помощью `os.pipe()` и `os.fork()` реализована передача данных от дочернего процесса родительскому. На примере FIFO рассмотрена связь независимых процессов через именованный канал. Также изучены сигналы и создание конвейера команд с помощью `subprocess`.

Выбор IPC зависит от задачи: pipe подходит для передачи потоковых данных между связанными процессами, FIFO — для обмена между независимыми процессами на одной машине, сигналы — для уведомления о событиях, а сокеты — для взаимодействия клиент–сервер.

### Контрольные вопросы

**1. Почему разделяемая память — самый быстрый и самый опасный механизм IPC?**

Разделяемая память позволяет процессам обращаться к одной области памяти напрямую, уменьшая накладные расходы на копирование данных. Однако одновременное изменение общих данных без синхронизации может приводить к состояниям гонки и повреждению данных. Поэтому необходимо использовать мьютексы, семафоры или другие средства синхронизации.

**2. Что произойдёт при записи в pipe, у которого закрыты все читающие концы?**

В Unix/Linux процесс обычно получает сигнал `SIGPIPE`. Если этот сигнал игнорируется или обрабатывается, операция записи завершается ошибкой `EPIPE`, которая в Python обычно представлена исключением `BrokenPipeError`.
