# Практическая работа № 2. Bash и системные вызовы

## 1. Цель работы

Освоить написание Bash-сценариев, научиться обрабатывать текстовые журналы и изучить взаимодействие пользовательских программ с ядром Linux посредством системных вызовов.

## 2. Реализация stats.sh

Скрипт `stats.sh` перебирает файлы `data/*.log`, подсчитывает количество строк, содержащих `ERROR`, вычисляет общее количество таких строк и определяет файл с наибольшим количеством ошибок.

Для подсчёта используется `grep -c`, для накопления суммы — арифметическая подстановка `$(( ))`, а для перебора файлов — цикл `for`.

## 3. Исследование системных вызовов

### Команда `strace -c ls`

Три наиболее часто встречающихся системных вызова:

1. **[openat]** — [открывает каталог или файл.].
2. **[close]** — [закрывает файловый дескриптор после завершения работы с ним.].
3. **[getdents64]** — [получает записи каталога, необходимые для формирования списка файлов и папок.].

### Команда `strace -c cat data/01.log`

Три наиболее часто встречающихся системных вызова:

1. **[openat]** — [открывает файл журнала для чтения.].
2. **[read]** — [считывает данные из файла.].
3. **[close]** — [закрывает файловый дескриптор после завершения чтения.].

Фактические названия и количество вызовов определены по результатам запуска `strace` в Linux.

## 4. Исследование `openat`

Команда `strace -e trace=openat cat data/01.log` позволяет наблюдать вызовы `openat`, выполняемые программой.

Перед открытием журнала динамически скомпонованная программа может открывать необходимые разделяемые библиотеки. Они содержат код, который нужен для работы программы. После загрузки зависимостей `cat` открывает целевой файл и читает его содержимое.

Конкретный порядок вызовов зависит от окружения и сборки программы.

## 5. Контрольные вопросы

### 1. Почему нельзя обращаться к диску напрямую из пользовательской программы?

Пользовательская программа работает с ограниченными привилегиями. Доступ к устройствам и файлам контролируется операционной системой через ядро и драйверы. Это обеспечивает безопасность, проверку прав доступа и совместное использование ресурсов.

### 2. Что дороже: вызов функции или системный вызов?

Обычно системный вызов дороже обычного вызова функции, поскольку требует перехода из пользовательского режима в режим ядра и дополнительных проверок. Обычный вызов функции обычно не требует такого перехода. При этом системный вызов не обязательно сопровождается переключением на другой процесс.
