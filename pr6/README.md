## Практическая работа № 6. Синхронизация

## Выводы

В ходе практической работы № 6 были изучены основные механизмы синхронизации потоков и проблема состояния гонки (Race Condition).

1. **Состояние гонки.** Был рассмотрен пример с общим счётчиком, который изменяется несколькими потоками. Без синхронизации результат может быть некорректным, поскольку несколько потоков одновременно обращаются к одной переменной.

2. **Использование мьютекса.** Для устранения состояния гонки был применён `threading.Lock()`. Критическая секция была защищена конструкцией `with lock:`, что позволило обеспечить корректное увеличение счётчика до 400 000. Проверка результата выполняется с помощью `assert`.

3. **Измерение производительности.** Было рассмотрено время выполнения программы с блокировкой и без неё. Блокировка может увеличивать время выполнения из-за дополнительных затрат на захват и освобождение блокировки, а также ожидания потоков. При этом она обеспечивает безопасность совместного доступа к данным.

4. **Синхронизация банковских операций.** При переводе денежных средств блокировка применяется к проверке баланса, списанию и зачислению денег. Проверка `assert` позволяет убедиться, что общая сумма на счетах не изменилась.

5. **Задача «производитель–потребитель».** Для обмена данными между потоками была рассмотрена очередь `queue.Queue` ограниченного размера. Она обеспечивает безопасную передачу элементов и ограничивает количество данных в очереди. Если очередь заполнена, производитель ожидает освобождения места.

**Общий вывод:** механизмы синхронизации необходимы для предотвращения конфликтов при доступе потоков к общим данным. Мьютексы помогают защитить критические секции, проверки инвариантов позволяют автоматически контролировать корректность программы, а потокобезопасные очереди упрощают взаимодействие между производителем и потребителем.
